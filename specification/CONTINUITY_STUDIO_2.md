# Continuity Studio 2 — Authoritative Production Specification

## Product contract

Continuity Studio 2 is a chat-first, project-based, continuity-aware, provider-independent movie production system. The structured database state is the sole authority for the movie. Chat, filenames, generated-image text, provider output, and historical prompts are evidence and interaction surfaces; none may override current approved structured state.

Continuity Studio creates no separate audio asset workflow. Seedance generates requested spoken dialogue, ambience, effects, music, and silence inside each video. The Studio owns the scenario, script, exact dialogue, numbered speaker binding, pronunciation, language and dialect, timing, actions, environment, continuity state, reference order, restrictions, and compiled Seedance request.

## Project state machine

The only forward lifecycle is:

1. Story Draft
2. Story Approved
3. Assets Pending
4. Assets Approved
5. Sequences Ready
6. Production Started
7. Final Review
8. Completed

The Studio derives this state from approved structured data and records every transition. It rejects illegal jumps. A changed prerequisite may move the project backward to the last legal state without deleting approved history.

## Data authority and schema

Data schema version 4 is current. Every archive records the version that created it, all migrations applied, and the supported version range. Versions 1–4 must migrate through normalization before use. D1 stores authoritative structured state, revisions, transaction guards, version histories, pins, lifecycle state, generation idempotency, checksums, import reviews, recovery points, and verification records. R2 stores original and generated bytes. Browser storage is never authoritative.

Every mutation is optimistic and atomic. A stale revision fails without partial writes. Every major operation—and currently every persisted mutation—creates a recovery point before changing the project.

## Permanent assets and files

One movie has one flat asset folder with no subfolders. Every visual production asset shares one permanent project-wide number. A regeneration keeps its number. A retired asset is never deleted and its number is reserved forever. Existing sequence links remain historical evidence. Orphan detection identifies active assets no longer connected to active sequences.

Portable filenames are deterministic: `NNN_NAME_GENERATED.png`. Names are normalized for Windows, macOS, ZIP, Unicode, length, and reserved device names while retaining the permanent numeric prefix. The export identity combines the project ID with the title so projects sharing a title cannot collide.

## Approved decision pins and inference

The user can pin character identity, costume, location, dialogue, camera rules, asset versions, and sequence versions through chat. A pin is an approved structured record. No inference, regeneration, provider result, or story edit may change it until the user explicitly releases it.

Routine filmmaking choices may be inferred. Every inferred value records its rationale, confidence, source, and editability. Inference never becomes a permanent lock without explicit user approval or an existing project rule.

## References, warnings, and confidence

Automatic reference roles remain editable. A user can restrict a reference to one role or exclude traits such as hair. Bindings store confidence and whether they were inferred. Low-confidence bindings require review before expensive generation.

Warnings have two levels. A Blocker prevents the affected expensive or impossible operation. A Recommendation remains visible but does not stop normal work.

## Generation and providers

Every generation request is rebuilt from current approved structured data. Historical prompt text is never submitted blindly. Entering generation creates an immutable per-attempt freeze containing scenario, exact dialogue, upload order, compiled prompt, continuity, provider, exact model version, capability revision, settings, data version, and structured-state hash.

Provider adapters implement capability refresh, deterministic translation, idempotent submission, status polling, and cancellation. Controlled queues enforce per-provider concurrency. One immutable request fingerprint maps to one job and one submission token. Timeouts poll the same provider request; they do not silently create another paid generation.

Every approved result records exact provider/model versions, settings, references, asset versions, scenario/dialogue versions, immutable snapshot, checksum-backed media source, and final source-map entry.

## Import, storage, recovery, and verification

Full archives restore structured state, chat, versions, pins, approvals, provenance, jobs, recovery, and original bytes. Old folders are analyzed before creation. Filenames and media produce a confidence-rated mapping for assets, references, sequence videos, prompts, and supporting data. The user approves that mapping before the project is created.

Storage management reports originals, previews, generated files, and cleanup candidates. Safe cleanup may remove only unused derived previews and failed unapproved generation media. Originals, approved assets, approved sequence results, final sources, provenance, and recovery data are protected.

Important media uses SHA-256. Reads and exports detect missing, corrupt, replaced, and duplicate bytes. Full archives and flat-asset ZIPs contain a deterministic manifest and are reopened and checksum-verified before download.

The chat command `repair this project` inspects relationships, files, numbering, references, approvals, dependencies, and continuity. It repairs only safe derived inconsistencies and reports ambiguous or missing source data for user review.

## Advanced control surface

Normal work remains in chat. An optional Advanced Control screen shows the lifecycle, dependency graph, blockers versus recommendations, inference confidence, pins, retired/orphan assets, version comparisons, and storage cleanup.

## Acceptance contract

Every release must cover:

- backward migration from every supported data version;
- legal and illegal state transitions;
- pin enforcement and explicit release;
- retirement and orphan detection without number reuse;
- deterministic portable naming and title-collision isolation;
- checksum, duplicate, corruption, missing-file, and archive-manifest verification;
- import mapping review before old-folder creation;
- generation queue limits, idempotent timeout/retry, and exact model pinning;
- prompt regression for dialogue speakers, numbered references, continuity, scene details, role overrides, and restrictions;
- end-to-end idea, approval, assets, bindings, planning, dialogue, generation freeze, regeneration, restart, export, restore, and final assembly;
- enforcement of the no-audio-asset policy.
